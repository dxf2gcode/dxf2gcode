# Historical documentation

DXF2GCODE previously hosted documentation and releases on SourceForge. The
current guide describes the development checkout on GitHub. Old instructions
can remain useful context, but should not be followed as current machine/profile
defaults without comparison with the current implementation.

## Where the old material lives

- [Historical wiki](https://sourceforge.net/p/dxf2gcode/wiki/Home/)
- [SourceForge downloads](https://sourceforge.net/projects/dxf2gcode/files/)
- [Existing forum](https://www.ltspiceusers.ch/forums/english-section.67/)

The repository maintains a provenance/URL inventory and local preservation
records for the wiki pages and attachments. Those records support migration
and attribution; they are not a public download of the raw archive.

## Old postprocessor examples

The inventory includes historical examples for a China laser cutter, styrofoam,
lathe, DXF and Python output. The current [five example references](../examples/index.md)
replace assumptions about old templates with explicit current semantics and
acceptance limits. They do not claim the old machine examples were tested on
today's software/controllers.

The original wiki page histories identify editors but do not settle complete
authorship or redistribution rights for every attachment. The new guide uses
original explanations and own examples instead of reproducing those pages.

## Material deliberately not republished

Uncleared wiki prose/screenshots, third-party panel drawings, the old Git-flow
illustration and raw discussion/mail attachments are not embedded here. Some
preserved discussion material includes personal contact details. The missing
external `Spant.png` remains unresolved; a newly authored tab diagram is clearly
identified as a new explanation rather than passed off as that historical image.

Requests to reuse a specific historical asset need its origin, applicable terms,
attribution and any necessary personal-data review. Until then, linking the
source or creating a new example avoids making an unsupported reuse claim.
See [License and credits](license-and-credits.md).

## Version context

Current D2G, application and postprocessor format migrations are described in
their current chapters. Old Python import namespaces and old Windows development
instructions are historical, not supported compatibility layers.
Release notes describe their dated versions; they are not instructions to
activate every old parameter under the current UI.

The next stable target is 2.0.0. Its release remains separate from documentation
completion and the outstanding package/platform/physical-machine acceptance.
See [Releases and downloads](downloads.md).
